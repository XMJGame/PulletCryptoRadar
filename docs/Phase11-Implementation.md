# Phase 11：BSC 地址核验与资金流

实施日期：2026-10-29（上海时间）。工程 PulletCryptoRadar，Vue 3 页面 /flows。链上分布与自选监控页面提供入口；资金流归入现有链上导航，避免增加导航条目引发布局位移。

## 数据与证据

本轮采用 BSC JSON-RPC Transfer 日志，而不是索引器有限条数的最近交易列表。链头、链 ID、日志、区块哈希和时间分别校验。默认 PublicNode，可用本机环境变量 PULLET_BSC_RPC_URL 指定 HTTPS BSC RPC；不在页面输入，不返回完整配置 URL，HTTP 日志禁用，错误不带地址中的密钥。只读取 chainId/blockNumber/getLogs/getBlockByNumber/getCode，不调用交易签名或发送方法。

依据：[BNB Chain JSON-RPC](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/)、[BSC RPC 方法](https://github.com/bnb-chain/bsc/blob/master/rpc/json-rpc-api.md)、[PublicNode](https://www.publicnode.com/)。BNB 官方公共节点部分禁用 getLogs，不能仅凭节点能返回链头就宣称能采集转账。本机 PublicNode 的 ARIA 日志探测实际返回 49 条，原始匿名响应见 Phase11-RpcLog-Probe.json。

单资产 BSC 自选试点：在具有当前可信链上绑定的启用自选中按资产 ID 取第一个，默认是 ARIA。首次从链头减去 64 个区块之后的最近 2,000 块开始，单次最多 500 块，每 120 秒采集；超过 120 个事件区块或 5,000 条日志时缩小范围而不跳过。单个区块仍过大则停在原断点并明确报错。64 是确认深度策略，不是对 BSC 最终性的密码学证明，RPC 也是外部数据源。

每轮先在单写入队列中预留最多 160 个 RPC 请求槽，再请求网络；串行请求间隔至少 150ms，默认预算每小时 6,000、每日 130,000 槽。预留与下次尝试时间持久化，重启不归零；实际请求往往远小于预留。预算独立于 Phase 10 的 Binplorer/GoPlus。429/方法限制/网络失败保留断点并冷却 15 分钟。页面刷新只读本地缓存。

## 精确值、去重与断点

仅接收指定合约、标准三主题 ERC20 Transfer、固定 32 字节 data、非 removed 日志。校验完整地址、交易哈希、日志序号、区块范围，以及每条日志哈希与对应区块头哈希一致。原始数量按 uint256 BigInteger 解码，保存十进制字符串；Vue 按字符串和 decimals 格式化，不经 Number 损失整数精度。

市场库新增 TokenTransfer、FlowCursor、FlowAttempt、FlowBudget、AddressInspection、AddressInspectionHistory；业务库 SchemaVersion=10。事件键为链/合约/交易哈希/logIndex，同一交易多个日志分别保存；重复日志不重复计数，有冲突则拒绝整批。转账、完整范围断点、尝试状态和地址核验在同一个 SQLite 事务提交，写入确认后才发布缓存，空区块范围也正常推进。保存时比较 ExpectedNextBlock，旧采集不能覆盖新断点。

续采前校验已保存末块哈希，提交前再读本批末块哈希；锚点变化会持久化 Halted，停止自动采集并保留证据，不静默清空历史或跨越分叉。恢复此类异常须人工核对节点和分叉点，再通过维护工具执行有备份的重扫；本轮没有提供一键删除断点的界面。普通进程重启则自动从已确认断点继续。

转账保留 90 天，地址代码核验保留最近记录及按区块的历史。只支持 BSC 直接事件，不做全链多跳归属、交易所成交识别、内部转账 trace、代币 rebasing 或跨链桥两侧的资金等价推断。

## ARIA 主要地址核验

针对当前 Top10 持币地址，按指定区块 eth_getCode 检查代码是否存在，保存区块号/哈希、SHA256 代码指纹、核验时间和来源，每 24h 更新。代码存在只能证明该区块有代码，不能证明项目方控制、签名人、归属、锁仓或 LP 用途；没有代码也不证明实际控制人。

[ARIA 官方分配说明](https://docs.playariagame.com/tokenomics/allocation-and-vesting)描述分配比例，但未提供足以据此确认本轮主要持币地址归属的精确地址证据。BscScan 读取返回 403，不能声称已在该浏览器直接核验标签；其他研究文章的团队/投资人归属没有自动导入为可信标签。当前保持归属待核对，不为了提高分类覆盖填入猜测。用户在链上页面提交经过核对的标签与 HTTPS 证据后，新的资金流视图会采用该标签；历史自选输入冻结当时的标签版本和证据。

## 资金流口径

只使用同链已核对标签区分 Project/Team/Investor/Treasury、Exchange 等。用户在自选配置中输入的钱包 role 只作为线索，不自动视作归属证明。Contract、未知地址和余额较大的地址均不直接认定为项目方。

同地址转账、铸造和销毁单列，不当作交易所转入；项目类之间的转账不计外部流出。项目类至交易所单列 ProjectToExchange；ProjectOutflow、ExchangeInflow、ExchangeOutflow 表示事件方向，不表示最终卖出或净流量。相同资产反复周转会重复产生实际事件，不能把总转账量解释为独立资产净变动。

统计为最近 1h 已观测下界，内部读取最近 24h 最多 10,000 条，明细展示最近 200 条。只有开始时间覆盖 1h、末块在两分钟内、已追至该次 RPC 链头的确认末块且读取未触达上限，才标示区块时间范围完整；地址标签覆盖仍独立不足。完整范围也不代表全部交易所地址均已识别。

数量/总供应量比例用同身份、45 分钟内供应量观测计算；缺失供应量保持 Unknown，不用流通量代替。区块时间与采集时间均不能处于未来；距已保存末块或缓存更新时间超过 10 分钟、失败状态、身份失效时，新鲜标记失效。

## WatchTower 1.2

在 1.1 上新增独立版本，不修改 1.0/1.1 历史计算。冻结 FlowSummary 及最多 20 个风险事件（原始交易、标签版本、证据与供应量比例），历史复算按版本路由，不查询当前标签或当前行情。

当价格及资产身份有效且资金流身份/时间通过，最近 1h 已观测项目类直接转入交易所占总供应量至少 0.01%，钱包风险代理分为 80；或项目类外部流出占比至少 0.1%，为 65。普通判断升级为 RiskIncreasing / High，但不会降低原有 CriticalRisk 或 ReduceRisk。未达到门槛、归属不足或数据缺失时钱包风险分仍为 null，不输出 0 或安全结论；置信度不因资金流新增而自动增加。固定门槛是研究代理，不是概率或交易指令。

个人提醒沿用原配置开关、冷却与 outbox，新增 1.2 版本也受关闭/暂停取消约束。未开启 ARIA 个人提醒、未修改成本及价格配置。Speculative-1.1 本轮保持原模型，钱包项仍未知。

## 接口与验证

- GET /api/flows：本地资金流、统计、区块断点、尝试状态、代码核验。
- POST /api/flows/{assetId}/retry：仅受控网络失败满两分钟允许请求重试；仍经持久化预算预留，不重置预算，不绕过 429/提供者冷却、无效数据或分叉暂停。仅更新排程，下次调度再采集。
- GET /api/flows/status：BSC 设置和自定义 RPC 是否配置，不输出端点或密钥。
- /flows：搜索地址/交易、归属筛选、交易/地址链接、代码核验证据；从 /onchain 和 /watchtower 进入。
