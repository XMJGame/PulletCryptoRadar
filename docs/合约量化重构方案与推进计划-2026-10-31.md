## 1. 我们要做成什么

做一个能够解释决策、控制风险、记录全过程、比较策略版本的合约量化研究与模拟执行工具。工具负责把“什么币值得看、什么条件可以操作、为什么拒绝、出了什么问题”变成有时间戳、可复查的证据。

保留三个核心资产：现有模拟账户及全部历史、妖币提前埋伏研究、代币快查。继续使用现有 Vue 前端和 .NET 后端，按职责重构内部模块；先保留可工作的采集、账本、身份核验和运行守护，不以重写代码数量作为进度。

每天净涨 1% 是用户的研究目标，不设为必须完成的交易任务。1000 USDT 的 1% 是账户权益扣除成本后增加约 10 USDT，不是某笔保证金的收益率。复利每天 1% 对应 30 天约 +34.8%、365 天约 37.8 倍本金，这是非常激进的持续收益要求，不能作为交付承诺。

第一目标是验证扣除手续费、滑点和资金费后是否存在正期望，并确认亏损路径能否承受。利润不设机械日上限；合格机会仍受组合风险和行情约束。达到日目标不会迫使继续交易或把账户风险抬高。

## 3. 产品只让你优先看四个入口

1. **量化工作台**：账户、持仓、今天真实净收益、市场环境、最新可执行计划、不开仓原因、系统健康。
2. **妖币埋伏**：独立的小市值及链上研究。展示证据、反证、缺失、阶段和来源时间，不混入合约日常策略成绩。
3. **代币快查**：输入名称/代码/合约，先消歧，再给当前参与条件、结构、项目和链上证据；保留历史快照。
4. **复盘与验证**：成交、成本、回撤、数据完整度、策略版本、样本外与前瞻结果。

其余行情、地址标签、映射、离线工具、网络设置放入次级工具区。原有路由和历史先保留兼容，不先删除数据或功能。

工作台的重要顺序是：现在有无风险 → 当前是否具备执行条件 → 为什么操作/不操作 → 需要看什么证据。避免研究入口和大段说明把持仓与风险挤到页面下方。

## 4. 统一决策链路

公共市场数据 → 标的身份与交易规则 → 数据质量检查 → 市场环境/特征 → 策略候选 → 成本与组合风控 → 模拟意向 → 后续报价模拟成交 → 持仓管理 → 不可改写的审计与复盘。

每个阶段都有独立状态。价格上涨不直接等于可以买，OI 变化不直接等于多空方向，研究评分也不直接等于成交许可。候选必须携带策略版本、参数哈希、输入来源/接收时间、条件值、失效位置和目标依据。

实现时拆成数据、策略、组合风控、执行、验证五个职责。模拟执行接口与未来真实经纪接口隔离。本计划只覆盖虚拟资金，不添加交易所真实下单权限。

## 5. 数据方案与当前缺口

| 数据 | 用途与实施要求 |
|---|---|
| 活跃永续合约、上线/交易状态 | 全市场粗筛；按当时可交易状态构建样本。当前活跃名单回测历史会有幸存者偏差，须明确标识 |
| 1h 原始 K 线、由闭合 1h 聚合的 4h K 线 | 趋势、波动、支撑压力。禁止使用未闭合 4h，也禁止用之后补齐的数据冒充当时已收到 |
| 最新价格、标记价格 | 入场与盈亏参考；强平检查用标记价格。不能用其他交易所现货冒充同一永续合约 |
| OI 数量序列 | 分开保留 1h/24h 变化、来源与接收时间。不能把价格导致的名义价值增长当作持仓数量增长 |
| 实际资金费记录、结算时间与周期信息 | 新账本按实际记录及方向结算，幂等防重复；缺失则标记估算/不完整，不写成真实零成本 |
| 买一卖一、必要时小档深度 | 点差、可成交量与滑点估计。重点查候选/持仓，不对几百币高频全深度轮询 |
| tickSize、stepSize、minQty、minNotional 等 | 模拟也要按真实交易规则向下取整数量，并重算风险和保证金 |
| 身份、流通市值、地址分布、解锁、项目公告 | 用于妖币研究和快查；跟合约执行基础数据分别标记覆盖，不假装所有币都齐全 |

运行基础先验收：区分只关日志/状态窗口、明确停止、进程崩溃、整机休眠和网络中断。保留用户需要的可见窗口，同时考虑把守护与观察窗口解耦；后台继续运行的规则必须明确呈现，不能把用户明确停止当成故障重新启动。要求完成单实例、幂等恢复、故障隔离演练及至少48～72小时连续采样观察，断档如实保留。Windows关机/休眠期间不能模拟持续监控；如需真正全天运行，再选择常开主机或VPS，不在本计划中自动购买或迁移。

当前最需要补的执行现实性是：资金费仍按保守固定假设、数量价格精度未完整执行、盘口滑点缺失。旧账本不能事后改写为新成本模型；新版本应另记成本模型及不足。

采集保持每月 30GB 的应用预算和请求计量，优先直连。全市场低频粗筛，最多约 60 个合约做深度分析；持仓和候选优先。具体标的数由流动性和数据完成度决定，不承诺每个交易对都有完整链上证据。

优先复用已验证的 Binance 永续数据；Gate/Coinbase 的用途按产品、合约、币种身份核实，不能只因同名就替换。供应方失败时记录降级，避免错误跨市场拼接。

## 6. 第一版只验证两类合约策略

以下是初始研究假设，不是最优参数结论。先登记版本，再运行；不通过一天收益倒推、挑选参数。

### 6.1 顺势回踩延续

假设：明确趋势中，回踩后的恢复比直接追逐排行榜更容易给出可解释的失效位置。

- 4h 识别趋势背景，1h 寻找回踩恢复；初始用 EMA20/60 和斜率描述趋势。
- 多头关注上涨背景下回踩结构/均线后恢复，空头使用对称逻辑。
- 记录触及位置、恢复条件、量能、ATR 与价格离结构的距离，不要求所有币先满足“72h 振幅≤12%”。
- 止损优先最近已确认的结构点加波动缓冲；结构不清楚则放弃。右侧确认 K 线必须已经闭合。
- OI、资金费和市场环境用于风险分层；缺失、极端拥挤和与假设冲突分别记录，不套用统一“只要 OI 增长 0～30%”门槛。
- 阻止距离合理失效位已经过远的追价；不因为它处于涨幅榜前几名就执行。

### 6.2 放量突破/破位延续

假设：高流动性标的突破已经形成的区间，并有量能及趋势背景时，可能出现延续；同时要防止假突破和末端加速。

- 初始研究区间为前 20～24 根闭合小时 K 线，之后固定一个版本，避免不断挑区间。
- 多头突破历史高位，空头跌破历史低位；量能参考之前 24h 中位数，初始量比假设约 1.5。
- ATR 描述突破缓冲与过热程度，记录突破后追价距离；必要时等待回踩确认，错过也不追远价。
- 突破位作为失效参考时明确标成“历史阻力/支撑转换假设”，不能冒称已经确认的新支撑。
- 排除盘口成本过大、上市基线不足、交易状态异常、极端资金费或数据失鲜的对象。

两类都可多可空，但不为了方向对称强行生成交易。初版不增加震荡网格、逆势摸顶抄底、马丁和无限补仓。保持少量假设，便于知道什么有效、什么无效。

### 6.3 市场环境

用 BTC/ETH 趋势、全市场涨跌分布和波动水平描述顺风、逆风、震荡及压力环境。顺风优先；逆风候选降低风险或要求更强证据；压力环境控制新仓。

环境分类本身也要验证，不给“牛市/熊市”标签附加未经检验的胜率。缺少基准数据属于未知环境，不自动当作中性通过。

## 7. 1000 USDT 模拟账户如何管

保留十个可重复使用的份额，每份保证金最多 100 USDT，同时最多五笔，不要求必须用满份额。旧 BTC 仓位保持原计划，不借重构强行平仓，也不提高或重置本金。

建议新版本从更保守的风险预算开始：

| 项目 | 新版本初始研究设置（未生效） |
|---|---|
| 常规单笔计划风险 | 权益约 0.4%，1000 U 时约 4 U；初始前瞻磨合阶段可用半风险 |
| 全部仓位计划风险 | 权益约 2%，且受绝对额度限制；遗留仓风险也计入 |
| 同向/高相关风险 | 初步最多三个同向仓；高相关组风险单独限额，相关数据不足时保守归组 |
| 保证金占用 | 每份≤100 U、五笔≤500 U，另留可用现金支付费用与波动 |
| 新仓杠杆 | 建议默认 2～5 倍，10 倍作为上限而非每笔必用；只影响新版本新仓 |
| 回撤 | 随回撤降低新仓风险，不因日目标未达成而加大仓位 |
| 20%亏损 | 保留用户要求：复盘提醒，不在 800 U 自动永久停盘，不补本金；风险按剩余权益继续缩小 |

先确定结构失效位置，再计算数量和杠杆。结构止损不适合 10 倍时，优先降低杠杆/减少名义仓位；仍不满足保证金、成本、精度或安全距离就不做。只减数量而维持相同逐仓杠杆，并不能消除百分比强平距离过近的问题。

风险单位应包括止损损失、往返费用及保守滑点缓冲。名义数量由风险额度、保证金上限、交易规则、流动性四项共同限制。止损是计划失效价，不是保证成交价；不能承诺不会强平、跳空或穿仓。

初始退出方案沿用可解释的结构思路：目标优先有效历史支撑/压力；没有合适目标时明确标记 R 倍风险投影。可先用 30%/30%/40% 分批与尾仓跟踪作为一版假设，重点比较扣费后结果。尾仓使用波动或结构跟踪，不因目标已达成任意全部平仓，也不无限期占用资金。

合约持仓周期和十倍币研究周期分别设置。某个代币有月度大行情想象，不构成长期维持高杠杆合约的理由。

## 8. 妖币埋伏与代币快查

### 妖币埋伏

目标仍是研究可能出现一个月十倍级行情的低市值标的，不把 BTC/ETH 当成这类样本。暂不宣称能够稳定提前预测十倍币。

研究顺序：

1. 准确识别链与完整合约，排除同名仿盘和跨链误绑。
2. 核验流通市值、流动性、代币交易状态及解锁/稀释风险。缺失不是零风险。
3. 地址分类后再解释集中度：交易所托管、销毁、桥、LP、归属合约与未知大户分别处理。前十地址集中不直接等于庄家控盘。
4. 连续观察余额/持有人/流向变化；交易所流入、持仓集中、成交/OI、价格波动和资金费联合解释，并保留反证。
5. 对照 LAB、MYX、BTW、TRB 等上涨样板，也加入未上涨、冲高回落、下架和流动性消失的失败对照，防止只研究赢家。
6. 输出研究阶段和证据覆盖，不先显示没有校准依据的“30天十倍概率”。研究池不自动接管合约策略。

链上地址关联仅作关系线索，区分直接转账、共同来源和可能的服务商中转；不能把图上连线说成同一实际控制人。外部浏览器/API覆盖或额度不足要直接展示。

### 代币快查

保持独立输入、候选确认、即时数据质量、结构与风险、项目/分配/解锁、地址证据和原始链接。结果按来源时间判断，旧报告不因刷新页面变成新报告。继续保存后续观察，比较当时判断与之后结果。

## 9. 验证路线与验收

### 工程验收

- 旧现金、仓位 ID、数量、成交与审计不被重置；迁移可逆、保留备份。
- 新策略只接收生效后信号；旧仓继续使用开仓时的退出与成本模型。
- 重启不重复成交、不重复资金费结算；暂停新仓仍能管理旧仓。
- 不把断网、休眠、缺失资金费/盘口当作正常覆盖或零成本。
- 逐项条件、版本、参数和执行拒绝原因能够关联到具体计划和成交。
- 自动检查未来输入、未闭合 K 线、价格数量精度、资金守恒、并发写入和成本重复扣取。

### 策略验证

1. 冻结假设与版本，登记尝试过的参数组合，保留失败结果。
2. 按时间顺序划分开发、验证和保留样本；不随机打散时间，不用同一段行情反复选参数再宣称样本外。
3. 用可获得的当时成分、历史状态和来源时间构建回放；缺少这些数据时明确限制，不能把当前 522 个活跃合约回看当作无偏全市场回测。
4. 回放模拟后续成交、点差/滑点、资金费、费用、精度；同一根 K 同时碰止损/目标时用更细数据或保守假设，不总取有利顺序。
5. 先做时间窗口对照和成本压力测试，再用之后的新数据运行模拟。离线历史回放与在线前瞻分别列示，不合并成一条“实盘收益”。
6. 按策略/方向/环境/流动性分组，统计净期望、R 分布、盈亏比、利润因子、回撤、连亏、尾部损失、成本和数据完整度。
7. 用按日/相关交易分组的方法评估不确定性，避免把同一行情中高度相关的多币交易当成独立样本。

### 第一轮评审门槛

以下是事先约定的评审标准建议，不是预测一定能通过，也不代表达到后即可直接实盘：

- 至少观察 30～60 个日历日，同时尽量获得 100～200 笔完整平仓；时间或样本不足就延长，不强行交易凑数。
- 扣除成本后期望为正，初步目标利润因子≥1.2、最大回撤≤10%；同时看样本不确定性和收益是否被少数币/少数日期支配。
- 跨多个连续留出窗口有一致性，压力成本下仍可接受；不只靠单一行情阶段获利。
- 有足够样本时检查分组重采样的净期望区间；证据不足保留“尚未证实”，不包装成稳定策略。
- 出现强平、记账差错或系统性覆盖缺口时，先处理执行与数据问题，再讨论参数。

一笔盈利、一周上涨或回测高收益都不构成稳定盈利证明。策略失败的交付也是有效结果：指出哪项假设不成立，停用或重写该版本，而不是继续堆过滤器掩盖亏损。

## 10. 推进阶段、交付与时间估计

时间按有效开发工作量估计，不是服务器自己等待就会完成开发的日期承诺。采集和模拟可以持续自动运行；版本重构与评审需要实际推进。范围扩大、接口限制和数据不足会改变工期。

| 阶段 | 参考工作量 | 交付 | 进入下一阶段的条件 |
|---|---|---|---|
| 0. 现状与问题基线 | 已完成本轮诊断 | 原账本基线、开仓漏斗、逐项条件、502+35测试及现场核验、本计划 | 确认原资产保留，明确当前未验证 |
| 1. 运行、数据与执行基础 | 约1～2个开发日，另需连续运行观察 | 守护/窗口退出行为及恢复核验、合约精度、资金费真实记录/周期、候选盘口、质量标记、迁移设计与备份 | 恢复演练通过，关键缺失能被阻止或明确标记；幂等与守恒检查通过 |
| 2. 新量化核心 | 约2～3个开发日 | 两类多空策略、环境特征、版本化计划、组合风控；先影子生成计划 | 输入无未来泄露，条件和拒绝可解释，原仓不受新规则改写 |
| 3. 可重复验证 | 约2～3个开发日 | 固定版本回放、留出窗口、成本压力、失败对照及报告 | 工程有效性通过；如效果不佳，记录并调整研究方向 |
| 4. 模拟接管与产品整理 | 约1～2个开发日 | 原1000 U账户连续保留，新仓按新版本模拟，旧仓原规则管理；四入口界面与复盘 | 迁移演练、风险检查、恢复测试和页面核验通过 |
| 5. 前瞻观察与迭代 | 至少30～60个日历日，样本不足延长 | 按日质量复盘、按版本绩效、阶段评审和保留/修改/淘汰决定 | 证据强度决定是否继续；不按目标收益倒推结果 |

总体预期：约 1～2 周有效开发量形成第一版较完整的量化实验工具；数据许可且基础复用顺利时可以更快。证明策略有效需要额外的市场时间。历史验证负面时也可以保留小风险模拟研究，但不能标记为已经通过盈利验收。

妖币与快查在全过程保持可用。新核心迁移按模块进行，每阶段单独验收，不把全项目一次性推倒后长时间不可运行。

## 11. 每天和每个评审周期做什么

每日自动记录：服务与采集断档、合约覆盖、未完成输入、候选/拒绝/意向/成交漏斗、持仓路径、净收益与成本。只有日初和当前权益均具备有效覆盖时才计算“今日账户收益”；不拿失鲜浮盈或中途起点替代日初权益。

日常人工/协作复盘：先排数据与执行问题，再看交易是否遵守冻结规则，最后看策略假设。盈利交易也检查是否偶然冒险，亏损交易也区分正常风险和错误执行。

参数评审按版本和预设窗口推进，通常按周看初步分布，按30天或样本门槛做阶段评审。每日可以修数据和记账缺陷，不因今天亏损就改明天的全部参数。重要策略调整另记生效时间和新版本，不回写旧结果。

## 12. 收益预期与交付预期

| 预期类型 | 可以明确追求的结果 |
|---|---|
| 工具质量 | 每笔有依据、仓位可计算、拒绝可解释、成本可核对、故障可发现、版本可比较 |
| 第一阶段策略 | 得到可证伪、可回放、可前瞻验证的少量策略；结果可能为负，需要淘汰 |
| 收益目标 | 研究长期正期望与可承受回撤；每日+1%作为对照指标，无法承诺实现或保证频率 |
| 大行情 | 通过分批与尾仓保留参与机会，妖币独立积累证据；无法保证抓到十倍/百倍 |
| 资金扩张 | 在有充分成本、回撤和前瞻证据后另行讨论；本计划不从1000 U模拟自动转入真实资金 |

本阶段最值得投入的不是“让它马上多开仓”，而是让新的交易逻辑和验证方法配得上账户的风险。新策略的输赢要让数据说话；工具必须如实展示失败。
