# 模拟盘备份、恢复与24小时验收

当前只使用虚拟资金。服务器照常通过“启动服务器.cmd”启动、“停止服务器.cmd”正常停止。关闭浏览器或观察窗口不停止后台服务器。连续观察期间保持电脑开机、网络可用且不休眠；程序不会修改系统电源设置。

## 当前目录的操作

在项目目录用PowerShell运行：

```powershell
# 在线备份到自动生成的新目录，不停止服务器
.\scripts\Simulation-Maintenance.ps1 -Mode Backup

# 校验已有备份；填写实际备份路径
.\scripts\Simulation-Maintenance.ps1 -Mode VerifyBackup -Directory 'G:\实际备份目录'

# 复制备份到独立新目录，试写并检查重启恢复/重复提交；不覆盖正式账户
.\scripts\Simulation-Maintenance.ps1 -Mode RestoreTest -Directory 'G:\实际备份目录'

# 明确建立新一轮观察起点，24小时从此刻起算
.\scripts\Simulation-Maintenance.ps1 -Mode StartObservation

# 查看最近一轮观察，读取正式日志/保存记录及本地API
.\scripts\Simulation-Maintenance.ps1 -Mode CheckObservation
```

维护工具位于`artifacts/simulation-maintenance/`，无需安装.NET SDK。它不启动第二个行情服务器，不请求交易所、不下单、不调整账户或策略。检查结果保存在`artifacts/simulation-observations/`，当前观察指针为`artifacts/simulation-observation-current.json`。原始API响应和每次检查分目录保存；baseline不可覆盖。提前检查只显示Collecting，不能提前验收24小时。

观察期间核对同一会话、含窗口首尾的心跳间隔、发布文件/配置/冻结控制摘要、开始前成交/资金费/复核/净值记录保留、净值采样间隔与有效性。心跳间隔超过90秒或会话变化需调查；净值间隔超过180秒保留数据缺口。可信净值分钟槽不等于所有候选的OI/盘口都完整，原始日报、数据源和执行覆盖响应须另外评审。存在未解决的原生异常时，到期仍保留该问题，不因一天未复发自动关闭。

## 备份与隔离恢复的范围

SQLite使用只读源连接和在线备份API，包含已提交的WAL记录；数据库逐个取得一致快照，业务账本在单库内一致，不宣称三个独立库同一毫秒的全局快照。占用仅有限重试，失败保留现场。复制配置及Data中的研究/冻结输入档案，排除活动锁、WAL/SHM及临时文件，不复制程序日志或转储。

完成后`backup.json`保存逐文件SHA256、业务账户和成交/费用/复核/净值/持仓观察/审计表摘要。验证还检查SQLite完整性与最新组合冻结报告的来源重放。失败备份可能留下INCOMPLETE及部分资料，应保持失败状态并另建目录，不能仅看文件存在就认为成功。

恢复演练强制使用原服务器外的新目录，不支持原地覆盖。先校验全部文件，再读取恢复账本，使用同时间、缺行情的隔离原引擎轮次试写；已有意向使用恢复的原始信号档案。市场缺失不得捏造成交。恢复后状态与计算结果一致，重复提交须被版本冲突拒绝，现金、持仓数量及成交/资金费数量保持。试写会改变恢复副本自身的修订号；完整原始备份保持不变。此练习不替代真实行情退出与新资金费样本。

## 固定发布包与回退

```powershell
.\scripts\New-SimulationPackage.ps1
```

该命令封装当前正在观察的程序、网页、独立守护、维护工具和操作说明，保存文件清单和ZIP摘要，标为候选版。包不包含Data、Logs或真实下单组件，包含本机配置，留在本机；本任务不上传。

当前包为“现有账户升级/回退包”，不作为新账户已经启用的证明。换机或恢复时，先在独立目录展开程序，使用校验通过的备份Data和配置；先做隔离恢复核对。需要接管时正常停止原服务器，保留原目录并确认没有重复实例，再启动新目录；不要让两个服务器管理同一Data，不删除锁文件绕过保护。回退采用相同正常停止和备份步骤，保留最新账户数据；不要用旧余额替换当前余额。结构不兼容的程序版本不得直接读取新库。

软件发布验收、连续运行验收与策略盈利评审分别记录。24小时到期不会自动开启真实交易，也不会自动调参。
