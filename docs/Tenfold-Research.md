# 30日十倍妖币研究：目标修订与第一轮诊断

用户明确的研究对象是一个月左右有可能达到起点价格至少十倍的小市值资产。普通大币的横盘趋势机会不应放进这个池子。本轮将入口改为“30日十倍妖币研究”，与涨幅榜/走弱交易继续分开。

## 已改变的规则

1. BTC、ETH及已列出的稳定币、黄金/封装锚定资产不进入十倍池；它们仍可作为全市场趋势/对照对象。
2. 流通市值不超过3亿美元暂作为研究上限。此上限、非托管Top10占总供应量至少30%、过去30日已达3倍的阶段标记，均是未校准研究假设，不是从样本证明出的有效阈值。
3. 已核验且新鲜的市值才可确认“小市值”。仅符号匹配的市值参考只能用于采集/核验优先级，不算通过。参考超过上限的资产本轮不优先进入十倍池，但不冒充已确认的排除结论。
4. 发现入口24h幅度放宽为-15%～20%，不再以72小时振幅≤12%作为十倍研究硬门槛。涨幅榜分组保留。
5. 独立计算非托管Top10：从已返回的排序地址中剔除已核验交易所、销毁、LP、桥地址后，取前十占总供应量比例。未知地址仍可能含托管或拆分地址；这不是同一操盘者的控制比例。
6. 集中度24小时变化只比较同一资产ID、链、合约、数据提供方、绑定修订及分类指纹；来源时间需相距23～25小时。分类变化或缺少旧快照保持Unknown，避免把重新标注当作吸筹。
7. 同时展示地址人数、人数变化、流通/稀释风险、过去30日涨幅及资金/钱包证据缺口。高集中度既是研究特征，也是集中抛售风险。
8. 30日价格基线至少需要721根连续小时线。采集缓存扩大到800小时，内部缺口或首次不足时才全量补齐，正常只补新增小时。原生1小时请求800条按官方LIMIT档位计5权重，其他频率仍保留原499条上限。

这些数据定义参考 [CoinGecko市值说明](https://www.coingecko.com/learn/what-is-market-cap-in-crypto)、[供应量方法](https://support.coingecko.com/articles/6758974979-coingecko-supply-methodology)及[Solscan持有人分析说明](https://info.solscan.io/solscan-token-holder-analytics/)。市值由价格和流通量决定；十倍市值情景不是所需资金流入量。地址标签有助于解释持有人结构，但不证明同一控制人。

## 实际历史诊断

完全离线读取原有校验通过的公开档案，没有补下载，没有写模拟账户。

| 项目 | 数量 |
| --- | --- |
| 合约 | 17 |
| 小时线 | 56,703 |
| 每24小时取一个研究起点 | 2,070 |
| 其后完整、无缺口30日窗口 | 1,456 |
| 未来小时最高价触及10倍 | 107个窗口 |
| 未来小时收盘价曾达到10倍 | 99个窗口 |
| 涉及的十倍收盘资产 | BTW、LAB、MYX、UNFI |

99个十倍收盘窗口中，只有3个（3.03%）满足旧72小时振幅≤12%；这组起点的72小时振幅中位数约31.00%，未达到十倍的窗口约16.46%。最新闭合小时成交额量比中位数分别约0.88和1.06。

这足以反驳“沿用旧窄幅门槛就是十倍币研究”的假定，但不能反推“振幅大/量能弱就应该买”。其中大量起点属于同一轮行情并相互重叠，17个币也是事后挑选；不能拿99/1456当作全市场概率、成功率或策略收益。没有独立留出集。

脚本保留起点前已知的72小时区间、24小时量比、24h/7d涨幅，未来高点、未来收盘最大倍数、30日终点倍数和最差倍数仅作为标签。缺口、尾部不足、未来接收数据不算完整标签。历史市值、地址归属、集中度和解锁数据尚缺，未使用今天的数据补回当年。

复现：`python scripts/research_tenfold.py`；数据见 `research/tenfold/Summary.json` 与 `Windows.json`。三项合成数据测试覆盖高点插针≠收盘十倍、缺口未知、未来结果不改变起点特征。

## 预测与模拟的边界

目标定义为“研究起点后30天内，价格达到起点10倍”；这不要求每天都涨，也不同于月末依然十倍。页面提供目标情景价和流通供给不变时的隐含市值，并明确不是目标价预测值。

本轮尚未训练出经过独立校准的十倍预测模型；概率字段固定Unknown。支持集中增加的快照只能进入“十倍假设待验证”，不能认定庄家吸筹或必将上涨。钱包同主体净买入、交易所库存、未来解锁/流通变化、完整市场中的失败样本仍是缺口。

十倍专属研究对象不自动提交旧A结构规则。若同币同时进入涨幅/走弱组，可独立接受趋势实验判断，但这不算十倍模型成交。已有小时冻结判断不重写，已有BTC趋势仓不因研究池定义改变而被强平。已有模拟风控与30GB/月、900MB/日预算保留。

旧池版本的恢复缓存不能作为新版当前池输出；等待新版首个快照，避免重启短暂重新展示BTC。原始旧快照保留用于审计。

## 验证

后端389项、前端29项及Python3项测试通过，Vue类型检查/构建通过。实际发布、资产排除、研究字段、数据源时间、预算和账本恢复结果见 `Tenfold-Validation.json`。底层运行时曾有一次原生SQLite访问异常退出；重启后继续观察，不能宣称已定位根因或长期稳定。

下一阶段应扩充按当时可交易全集采样的正例/失败对照，并核验小市值身份和链上时序，再进行按事件分组、按时间留出的预测检验。没有这些数据前，不给出伪造的十倍成功率。
